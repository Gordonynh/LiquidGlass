# 液态玻璃

把 ClassIsland 状态栏换成苹果液态玻璃（Liquid Glass）质感。

## 不是又一个毛玻璃

常见的「玻璃拟态」实现只有两步：背景模糊 + 一层白色半透明。那样出来的是**贴纸**，
不是玻璃 —— 没有厚度、没有曲率，边缘是一条等宽的死线。

这个插件把玻璃当作一块**有厚度的实体**来算。所有边缘效果都从圆角矩形的
有向距离场（SDF）推导：

| 层 | 作用 |
|---|---|
| 接触投影 | 两道：宽的软投影给纵深，1 像素的接触投影让底边「落」在东西上。强度跟着背景走 |
| 折射背景 | 按 Snell 定律把视线折进玻璃，再投到虚拟背景平面上取色 |
| 散射 | 光穿过玻璃厚度时的散射，σ = 0.45 × 厚度。少了它折射内容全锐，像哈哈镜不像材质 |
| 动态范围压缩 | 背景很花时把对比压向均值，保证条上的字压得住 |
| 染色 | **按背景亮度索引**的色阶，不是糊一层白 |
| 内侧暗边 | 紧贴亮边的里侧压一道暗，亮暗相邻才有厚度 |
| 镜面高光 | 贴边的亮弧，**两盏对向光**；颜色取自背景，不是自己发白光 |
| 菲涅耳边缘 | 法线越接近掠射越亮 |
| 边缘色散 | 红蓝在边缘错开极小的一点 |

形状本身也讲究：圆角用 **L⁴ 超椭圆**而非正圆（正圆在圆角接直边处曲率不连续，
高光弧上会出现肉眼可见的折角），厚度剖面用 **squircle** 而非四分之一圆
（圆形剖面在拱面接平面处留接缝，拉成长条时非常明显）。

整条管线跑在 GPU 上：一趟裁剪、两趟可分离高斯（散射）、一趟统计（背景均值与对比度，
靠 mipmap 逐级平均，不回 CPU）、一趟主绘制。实测 **0.3 毫秒一帧**。

> **CPU 退路**：ClassIsland 落到软件渲染时（虚拟机、远程桌面、驱动异常）拿不到
> GPU 互操作，自动降级成「只有玻璃外壳、没有折射」，逐像素算好缓存成位图。
>
> 一开始试过用 SKSL 着色器走 Skia，实测走不通：SkiaSharp 官方的 `libSkiaSharp.dll`
> 没编进 SkSL 的 CPU 解释器（SkVMGenerator），**软件渲染下能编译、一绘制就崩**，
> 而且是访问违例，`try/catch` 拦不住，会把整个 ClassIsland 带走。
> 而软件渲染是实际会走到的回退路径，所以那条路不能当主路径。
> 现在的 D3D11 管线和 Avalonia 的渲染模式无关，软件渲染下也不会崩，只是不生效。

## 与像素流动共存

本插件**只替换状态栏那块背景板**（`Border.line-background`），不碰任何控件模板。
通知那一整套仍归像素流动管，两个插件互不干涉：平时是玻璃，来通知时是像素流动。

> ⚠ 主题按启用顺序依次叠加，后加的覆盖先加的。
> 要两个都生效，「液态玻璃」必须排在「像素流动」**之后**启用。
> 设置页会检查顺序，不对会提示。

<details>
<summary>走过的一条弯路，记下来免得再走</summary>

`MainWindowLine` 有两套模板，曾经以为「精简模板」是无通知时用的，于是去覆盖它。
其实 `IsNotificationEnabled` 是 `MainWindowLineSettings` 上的**每行开关**
（编辑模式里勾的「这一行显示通知」），默认为 `True`，
所以状态栏一直走完整模板，覆盖精简模板等于什么都没做。

更麻烦的是 **ClassIsland 的主题加载失败是静默的** ——
`XamlThemeService` 的 catch 只写 `IsError`，不写日志。所以「日志里有『正在加载主题』」
并不代表加载成功。插件里那个 `ThemeWatch` 就是为此加的：把 `IsError` 和异常落盘。
</details>

## 设置

应用设置 → 液态玻璃。可调边缘厚度、高光强度、光源方向、色散、染色。

## 「不回 CPU」和「屏幕捕获」不矛盾

这两句话经常被读成互相打架，所以说清楚：**「屏幕捕获」有两种，差别在结果落在哪。**

| | 传统抓屏（GDI BitBlt） | DXGI 桌面复制（本插件用的） |
|---|---|---|
| 捕获结果 | 系统内存 | **显存** |
| 路径 | GPU → 内存 → 再传回 GPU | 从头到尾在显存 |
| 实测 | 8.3 ms 一次 | 0.3 ms 一帧（含整个着色器） |

本插件全程没有 `Map`、没有 Staging 纹理、没有 CPU 访问标志：
`AcquireNextFrame` 拿到的就是一张 `ID3D11Texture2D`，
`CopyResource` 是显存到显存，着色器直接采样，结果写进共享纹理交给 Avalonia。
**像素一次都没有进过内存。**

但桌面复制**确实是捕获 API**——它拿的是 DWM 合成之后的整屏。
下面那两条代价来自这一点，与性能无关。

## 折射需要背后的像素

这是决定它像不像玻璃的唯一一件事，所以说清楚。

状态栏是置顶的，背后的内容不在本程序的画布里，拿不到。几条路实测的结果：

| 路子 | 结果 |
|---|---|
| 读自己的画布快照 | 只能读到本程序画的东西，背后一律是全透明 |
| DWM 亚克力 | 那些像素由 DWM 在 Avalonia 表面<b>之下</b>合成，进不了本程序的缓冲区；而且亚克力作用于整个窗口矩形，不是这条胶囊 |
| 抓 Progman/WorkerW 壁纸 | Windows 11 上已失效，取回来全黑（ClassIsland 自己那份 `WindowCaptureHelper` 也正因此整个包在 `#if false` 里） |

实际采用的是 **DXGI 桌面复制**。它拿的是 DWM 合成之后的整屏，
所以背后是壁纸、是课件、还是别的窗口，一律照实折射，不需要任何猜测或退化处理。
代价是必须给 ClassIsland 的窗口设 `WDA_EXCLUDEFROMCAPTURE`，
否则每帧都在折射上一帧的自己，逐帧套娃。

> ⚠ 那个标志会让状态栏**在 Zoom、腾讯会议、OBS 和投屏里看不见**。
> 要录课或投屏就把设置里的折射关掉——关掉之后只剩玻璃外壳，也不再捕获任何东西。

## 三个只在别的机器上才会犯的错

都是在「单屏、不接投影、一直停在桌面」的开发机上碰不到的，记在这里。

**宿主的透明度必须一起覆盖。** ClassIsland 把这块背景板的 `Opacity` 绑在
「主界面透明度」上（`MainWindowStylesAssist.BackgroundOpacity`，默认 0.5）。
只覆盖底色不覆盖它，玻璃就是按半透明画上去的，背后的真实画面直接透过来——
屏幕上同时存在一张清晰原图和一张被折射位移过的副本。
**壁纸上完全看不出来**（平滑的东西叠上自己还是它自己），
一开程序就是明显的重影，看着像「折射的纹理被放大了很多倍、位置偏右」，
其实是两张图叠在一起。所以本主题把它压回 1：
**启用本插件后，主界面透明度不再影响状态栏。**

**桌面复制是按显示器的。** 交出来的纹理，坐标从**那台显示器自己的左上角**算起；
而 Avalonia 的 `PointToScreen` 给的是**整个虚拟桌面**的坐标。
单屏、且这块屏就在虚拟桌面原点时两者恰好相同，所以单屏机器上一直没露馅；
一接投影或第二块屏，折射位置就整体偏掉。现在按状态栏所在的那块屏挑显示器，
减掉它的 `DesktopCoordinates` 左上角；状态栏被挪到另一块屏上会自动重挑。

**复制会失效，而且失效之后不会自己恢复。** 切换全屏程序、改分辨率、DWM 重启、
锁屏回来，都会让 `AcquireNextFrame` 之后一直失败（`DXGI_ERROR_ACCESS_LOST`）。
只写「抓不到就沿用上一帧」的话，画面会**永远停在失效前的那一帧**：
玻璃里折射的还是几分钟前的桌面，和背后实际显示的内容对不上。
现在除超时外一律判定作废，下一帧重建。

> ⚠ 排除捕获的标志会被宿主冲掉：`MainWindow.UpdateWindowFeatures` 按
> 「阻止窗口捕获」这个设置把 `DisplayAffinity` 重设回 `WDA_NONE`，
> 而它挂在窗口激活事件上——**用户点开别的程序就会触发**。
> 所以每帧回读一次、失效就补设，成本是两次 user32 调用。

排查这类问题的落脚点是插件配置目录下的 `status.txt`：
每 900 帧记一行，含控件尺寸、缩放、屏幕位置、**实测到的宿主不透明度**、
所在显示器与其矩形、桌面纹理尺寸、裁剪原点。
状态栏被排除在屏幕捕获之外，截屏拍不到它，所以现场只能靠这个文件说话。
